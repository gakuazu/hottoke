## 経緯（ios-engineerとの対話について）

ワイヤーフレーム確定前に`ios-engineer`へSwiftUIでの実装可否・工数感（メイン画面のSpriteKit＋Core Imageカーネル構成、保存/共有画面のアスペクト比選択、ギャラリーのJSON+画像構成、確認ダイアログ等）を確認するメッセージを送ったが、`CLAUDE.md`に記載済みの既知の制約（非fork型サブエージェントからは`ListAgents`/`SendMessage`で他の個別起動サブエージェントに直接到達できない）のとおり、`No agent named 'ios-engineer' is reachable`というエラーになり到達できなかった（1本目・2本目と同じ事象）。

そのため本ワイヤーフレームは、`docs/18-app3-spec.md` 8章（MVPスコープの切り分け・実装コストの考え方）とios-engineer向けの一般的なSwiftUI実装コスト感（標準コンポーネントを最大限使う、独自表現は砂キャンバスの陰影のみに限定する）を自己判断で反映した上で作成した。オーケストレーター仲介フローでios-engineerが起動された際に、本書（特に画面2のSpriteKit+Core Imageオーバーレイ構成と画面3のアスペクト比書き出し）の実装可否・工数感を確認し、指摘があれば簡素化して最終確定することを推奨する。

## デザイン方針の要点

- **iOS HIG準拠・SwiftUI実装容易性**: NavigationStack（大見出し・標準アイコンボタン）、3タブのTabView（庭/ギャラリー/設定）、グループ化リスト（`Form`/`List`相当）、confirmationDialog相当のボトムシート、標準的な角丸ボタンなど、SwiftUI標準コンポーネントで素直に実装できる構成に統一。独自表現は「砂キャンバスの陰影プレースホルダー」のみに限定した。
- **陰影表現のワイヤーフレームレベルでの可視化（最重要・オーナー要件対応）**: 溝を単純な1本線ではなく、**同一SVGパスを3重に重ねて描く**ことで立体感を近似した。
  1. 右下にわずかにオフセット＋ぼかした暗い色のストローク（影側）
  2. 左上にわずかにオフセット＋ぼかした明るい色のストローク（光が当たる側＝ハイライト側）
  3. 中央に細く濃い「コア線」（溝そのもの）
  
  さらに、曲線が自己交差する箇所はコア線を太く・濃くすることで「同じ場所を何度もなぞると溝が深くなる」（仕様書2.3節）という振る舞いを静止画でも伝えられるようにした。これはあくまでワイヤーフレーム上の近似表現であり、実装はCore Imageカーネルによる高さマップ蓄積＋法線再構成シェーディング（仕様書2.2節のMVP最低基準）に置き換わる前提を画面1・2の注釈に明記した。砂のベースには微細なグレインノイズ（重なる2層のドットパターン＋`multiply`合成）を薄く重ね、単色べた塗りに見えないようにしている。玉は放射状グラデーション＋鋭いスペキュラハイライトで金属球らしさを表現した。
- **正方形キャンバスの一貫した採用**: 11章で決定済みの方針に従い、画面2（メイン）・2a・3（プレビュー）・4（ギャラリーサムネイル）・4bのすべてで正方形比率のキャンバス表現を統一し、Instagramの1:1グリッドに馴染む前提を画面設計全体で裏付けた。
- **保存/共有画面のアスペクト比導線（5章対応）**: 1:1/4:5/9:16を横並びの選択式カードで提示し、v1では3種すべてを無料開放（仕様書5.1節の記述に整合）。動画書き出し・4K書き出しのみPROロックとして明確に区別した。
- **収益モデル（基本無料＋サブスク主軸＋買い切り併設、6章）の一貫した可視化**: 画面2のロック無し砂/玉チップ（無料デフォルトのみ選択可）、画面3の動画/4K行のPROロック、画面5の砂質感・玉・BGMのロック行＋PRO訴求バナー、画面6のペイウォール本体（サブスク2プラン＋買い切り単発パック2種＋購入前必須表示一式）の4箇所で一貫して「無料でできること」と「PROで解放される範囲」を提示した。v1では実購入を行わない（StoreKit Configurationのローカルテストのみ）ことを画面5・6の両方に誠実に明記している。
- **「ゴールのない自由創作」という差別化の明記（4章対応）**: 画面2にスコア・タイマー・クリア演出を一切配置せず、玉が直接タップ操作できないことを注釈で明示。画面4bでは「続きを描く」機能（v2）を画面上に出さないことで、v1の実際の機能範囲とユーザーの期待値のズレを防いだ。
- **プライバシー配慮の明記（10章対応）**: 画面1・5の双方で「モーションセンサーは許可ダイアログ不要」である旨を明記し、1本目「カレイド日記」（Motion&Fitness権限が必須）との技術的な違いが利用者にも伝わるようにした。
