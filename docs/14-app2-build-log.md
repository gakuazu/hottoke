## 2026-09-12: MVP(v1)の土台を実装（プロジェクト作成〜ビルド確認）

### やったこと（平易な説明）

1. **新しいGitHubリポジトリ`gakuazu/kaoplay`を作成した。**
   1本目と同じく非公開リポジトリで、`gh`コマンドで作成・クローンした。

2. **Xcodeプロジェクトを作成した**（`app/`フォルダ、XcodeGenで組み立て）。
   - 1本目と同じ理由（このマシンではXcode本体が動かせない）で、「XcodeGen」という補助ツールでプロジェクトファイルを組み立てた。
   - 今回は補足: XcodeGen自体をこのマシンにインストールしようとしたところ、Homebrew経由では「Xcode本体が必要」という制限に当たりインストールできなかった。そこでXcodeGenの公式GitHubが配布している「すでにビルド済みの実行ファイル（コンパイル不要）」をダウンロードして使う方法に切り替え、無事に動かすことができた。Xcode本体は一切使わずに済んでいる。

3. **「ARKitの顔トラッキング」と「ゲームのルール」をはっきり分離する設計にした。**
   - `docs/13-app2-feasibility-review.md`（このエージェント自身が前回書いたレビュー）で提案した方針どおり、「カメラで表情を検出する部分（`FaceTrackingService`）」と「検出した表情を使ってゲームのルールを判定する部分（3つのゲームそれぞれのロジック）」を完全に別ファイルに分けた。
   - ゲームのルール部分はARKit（実機のカメラ機能）を一切使わない、普通のSwiftの計算だけでできている。そのため、実機が無いシミュレータやGitHub Actions（クラウド上の自動ビルド環境）の上でも、「表情が検出された後、ゲームが正しく反応するか」を自動テストできるようにした。
   - カメラと実際につながる部分（`FaceTrackingService`）は、画面が切り替わるたびに作り直さず、アプリ全体で1つだけ共有する仕組みにした（画面を切り替えるたびにカメラが再起動してもたつく、という問題を避けるため）。

4. **デバッグ用の「モックモード」を用意した。**
   - 開発中（配布版には含まれない）限定で、画面下にスライダーが並ぶパネルを出せるようにした。このスライダーを動かすと、実際に笑ったりウインクしたりしなくても「笑った強さ0.8」「左目を閉じた強さ0.9」のような仮の値をアプリに送り込める。
   - これにより、TrueDepthカメラが無いシミュレータ上でも、「笑顔ジャンプでちゃんとジャンプするか」「表情ビンゴの9マスが正しく開くか」といったゲームの動作を目視確認できる。実機を使った確認の手間を減らすための工夫。

5. **ミニゲーム3本のルールを実装した。**
   - **①笑顔ジャンプ**: 笑顔の強さが一定を超えるとジャンプし、障害物を避けられたらスコアが増える。避けられなかったらゲーム終了。
   - **②表情ビンゴ（差別化の核）**: 3x3の9マスに「笑顔」「左ウインク」「右ウインク」「口開け」「眉上げ」「びっくり目」「大笑い」「両目パチ」「にっこり」のお題を配置。該当する表情を作るとそのマスが開く。一度開いたマスは表情を戻しても閉じない。縦横斜めのどこかが揃うとビンゴ成立。「タイムアタック（ビンゴが揃うまでの速さを競う）」と「フリープレイ（焦らず9マス全部埋める）」の2モードを用意した。
     - 「びっくり目」は、口を開ける・両目を見開く・眉を上げる、の3つが同時に起きているかを見る少し複雑な判定にしている（`docs/13-app2-feasibility-review.md`で「単純な閾値判定だけでは済まないマスがある」と指摘していた点への対応）。
   - **③ウインク・シューティング**: 左右どちらかからランダムに出てくる標的を、対応する側のウインクで撃つ。両目同時の自然な瞬きは「誤操作」として無視するようにしている（ウインクしたつもりなのに両目とも強く反応した場合は発射しない）。

6. **画面を実装した。**
   - **非対応機フォールバック画面**: TrueDepthカメラが無い端末（iPhone SEなど）で開くと、「この端末では利用できません」という説明だけが出て、そこで安全に止まる（クラッシュしない）。
   - **オンボーディング画面**: カメラの許可を求める前に、「表情検出にしか使わない」「映像は保存・送信しない」ことを説明する画面。
   - **カメラ権限拒否のリカバリー画面**: 「端末は対応しているのに、カメラを許可してもらえなかった」場合専用の画面。非対応機の画面とは別物として用意し、「設定アプリを開く」ボタンを置いた（`docs/13-app2-feasibility-review.md`で指摘していた、抜けていた画面）。
   - **ホーム画面**: 3つのミニゲームのカードと、「追加ミニゲーム3本（近日公開）」という鍵アイコン付きの予告カードを表示。
   - **ミニゲームプレイ画面**: 丸いカメラプレビュー（自分の顔が映る）と表情の強さバーを共通パーツにして、3ゲームで使い回している。
   - **結果画面**: 今回のスコアと自己ベストを横棒グラフで比較表示。自己ベストはこの端末内だけに保存し、他の人との共有やオンラインランキングは今回は実装していない（v2予定）。
   - **設定画面**: カメラ権限の状態、プライバシーの説明、追加ミニゲームの買い切り予告（「現在はテスト環境のみで実際の購入はできません」と明記）を表示。

7. **GitHub Actions（自動ビルド）の設定を作った**（`.github/workflows/ios-build.yml`）。1本目とほぼ同じ仕組みで、コードをpushするたびに「コンパイルが通るか」「ユニットテストが通るか」「実機向けの署名なしIPAが作れるか」を自動確認する。

### 実機へのインストール方法（オーナー向け）

1. 上記の実行結果ページ（または`gh run list --repo gakuazu/kaoplay`で最新の成功結果を確認）を開き、「Artifacts」から`KaoPlayApp-unsigned-ipa`をダウンロードする
2. 中の`KaoPlayApp-unsigned.ipa`を、SideloadlyでPC/Macに接続したiPhoneに無料Apple IDで署名してインストールする
3. 署名は7日で失効するため、1週間ごとに同じ手順でインストールし直す

**重要な注意**: このアプリはTrueDepthカメラ（Face ID対応機種のカメラ）が無いと動作しない。iPhone X以降（実質iPhone XS以降、iOS 17対応機種）のFace ID対応モデルでのみ遊べる。iPhone SEシリーズなど対応していない端末では、起動後に「この端末では利用できません」という案内だけが表示される（これは正常な動作で、クラッシュではない）。

また、GitHub Actions上のビルド確認では「コンパイルが通ること」「非対応機の画面が正しく出ること」「ゲームのルール部分の自動テストが通ること」までしか確認できない。**実際に自分の顔でどのくらい検出されるか、閾値の感度が適切かは、実機でのテストでしか確認できない**（`docs/13-app2-feasibility-review.md`で事前に説明していた制約どおり）。Sideloadlyでインストールした後、実際に遊んでみてのフィードバックをお願いしたい。特に以下の点を教えてほしい:

- 笑顔ジャンプ: どのくらい強く笑うとジャンプするか、感度は合っているか
- 表情ビンゴ: 9マスそれぞれ、意図した表情で本当に開くか。逆に意図しない表情で誤って開いてしまうマスがないか
- ウインク・シューティング: 片目ウインクと両目の自然な瞬きがきちんと区別されているか
