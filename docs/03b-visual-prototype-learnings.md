# Phase 2 補足: ビジュアルプロトタイプで固まった仕様

作成日: 2026-08-26
担当: オーナーとの対話によるビジュアル検証（ブラウザCanvas 2Dプロトタイプ）
プロトタイプURL: https://claude.ai/code/artifact/6dd54eb3-cdcd-4a74-897c-b0a035b14862

`docs/02-spec.md`・`docs/03-design.md`の後、Swift実装に入る前にブラウザ上で模様の描画表現と操作感を試作・反復した。ここで固まった内容はSwift実装（Phase 3）の直接の参考仕様とする。

## 画面レイアウト

- 円形の「アイピース」枠は不採用。**画面全体をキャンバスにするフルブリード**が正しい方向。操作パネルは画面の半分を占めないよう、折りたたみ可能な最小限のガラス風オーバーレイ（半透明・ぼかし）に留める
- ヘッダーも最小限（アプリ名の小さなピルのみ）にし、模様そのものが画面の大部分を占めるようにする

## 模様の描画表現（「本物の万華鏡らしい繊細さ」の核心）

- ソフトなグラデーションの円（ボケ味）ではなく、**輪郭のはっきりした「ガラス片」形状**（ひし形・鋭角三角形）を敷き詰める。角に軽いハイライトのストローク（縁取り）を入れると硬質感が出る
- レイヤー構成: 大きめの「面（facet）」で色の基調を作り、その上に大量の小さな「シャード」で密度を出し、中心から放射する細い「光の筋（ray）」で鏡面反射の線構造を加え、最後に小さな輝き（spark）を散らす
- **透明感**: 塗りは`multiply`（乗算）合成にする。ガラス片同士が重なった部分は色が掛け合わさって濃くなり、重ならない部分は下地が透けて薄く見える——実際に色ガラスを重ねた時の見え方に近い。角に小さな白いハイライト（`lighter`合成）を加えると光を反射しているように見える
- 背景のベタ塗り・放射状グラデーションは不要。ガラス片同士の隙間は暗く抜けるままでよい（本物の万華鏡のミラーの継ぎ目に近い）
- 密度は「背景が見えないくらい」を目安に大量に敷き詰める

## 対称性の実装（重要な技術メモ）

- 万華鏡の対称性は「扇形1つ分の模様」を生成し、それを対称数（n）だけ回転複製して作る
- 生成する模様の角度は**必ず扇形の角度幅（2π/n）に収める**こと。全方向にランダム配置すると、対称数分の1しか実際には表示されず、残りは描画コストだけ払って画面に出ない無駄が発生する
- 偶数番目・奇数番目の扇形は、**単純な上下反転ではなく「扇形自身の中心線（二等分線）を軸にした反転」**にする必要がある。軸を間違えると隣の扇形の範囲にずれて重なり、対称数の半分しか埋まらない不具合になる
- パフォーマンス: 扇形の中身は毎フレーム1回だけオフスクリーンバッファに描画し、それを画像として対称数の回数だけ「スタンプ」のように複製する。個々の形状を対称数×形状数ぶん毎回描き直すと、対称数や密度を上げた時に極端に重くなる

## 操作・モーション

- **ドラッグ**: 模様全体を回転させる（傾ける操作の代替）
- **端末を振る/傾ける**（`devicemotion`/`deviceorientation`）:
  - 傾き（tilt）→ 模様の回転にゆっくり反映
  - 振った方向（加速度のx/y）→ 模様全体がその方向に一時的に「流れ」、バネで元の配置に戻る（ビーズが管の中で動く感覚）。**変位量は控えめにする**こと。大きすぎると模様が扇形の描画範囲外まで押し出されて見えなくなる
  - 強い振り（加速度の変化が閾値超え）→ 模様の配色・配置そのものを再生成（Wordle的な「今日の1つ」ではなく、この手動モードでは何度でも試せる）
- 揺らした瞬間の「ポン」という視覚フィードバック（中心からの衝撃波リング、模様全体のわずかな拡大→戻り）があると手応えが出る
- アイドル時もゆっくり回転・脈動させ、静止画に見えないようにする

## 安全設計（実装時の教訓）

- 新旧の模様をなめらかに切り替える処理（モーフ）で、生成数が毎回変わる複数種類の形状を配列のインデックスだけで対応付けると、異なる種類同士を誤って補間してしまい不正な値が発生することがある。**同じ種類同士でのみ補間する**ガードが必要
- 何らかの想定外の状態でも描画ループ自体は止めない（1フレームの失敗が永久的な「消えたまま」にならないようにする）設計にしておくと事故が起きにくい
