## 2026-09-13: MVP(v1)の土台を実装（プロジェクト作成〜ビルド確認・陰影表現の初期プロトタイプ）

### やったこと（平易な説明）

1. **新しいGitHubリポジトリ`gakuazu/sandgarden`を作成した。**
   1本目・2本目と同じく非公開リポジトリで、`gh`コマンドで作成・クローンした。ビルド・配布の方針（XcodeGenでプロジェクトを組み立て、GitHub Actionsでビルド・テスト、署名なしIPAをSideloadlyでインストール）もこれまでと同じ。

2. **`docs/20-app3-feasibility-review.md`（自分自身が前回書いたレビュー）の推奨をすべて反映した。**
   - **陰影表現は、まずApple純正の組み込みフィルタ（`CIHeightFieldFromMask`＋`CIShadedMaterial`）で作った。** 自分で1から光の計算式を書く（自作CIKernel）方式は使わず、Appleがあらかじめ用意している「グレースケール画像を高さ地図として扱い、光の当たり方を計算して陰影をつける」機能をそのまま利用した。玉が通った場所を少しずつ「彫る」処理は、1本目のカレイド日記で使った「ぼかした円を描き重ねる」方法をそのまま流用した。
   - **玉の物理演算（傾けると転がる・慣性・摩擦・壁での跳ね返り）は、SpriteKit（ゲーム用の物理エンジン）を使わず、自分で書いたシンプルな計算だけで実現した。** レビューでは「SpriteKitを見えない物理エンジンとしてだけ使う」ことを推奨していたが、実際に必要な計算（傾きに応じて少しずつ加速する・徐々に減速する・壁で跳ね返る）はニュートン力学の基本的な計算だけで十分再現できると判断し、SpriteKit自体を使わない、より単純でテストしやすい形にした。これにより「見た目の描画とは別に物理エンジンだけ動かす」という難しい設計を避けつつ、レビューが最も懸念していた「2つの描画の仕組みを画面上で重ねる」問題も最初から発生しない。

## 2026-09-13(2回目): 陰影表現の見た目を磨き込み（ノイズを弱める・立体感を底上げ）

前回生成したプレビュー画像（`sand-shading-preview`、実行結果 https://github.com/gakuazu/sandgarden/actions/runs/34751736499 ）をオーナーが実際に確認し、「インスタ映え」という最重要要件に対して次の2点の見た目の改善指示を受けた。

1. 砂の粒状ノイズが、テレビの砂嵐のようにザラザラ・チカチカして見える。
2. 明るい色の砂（金色など）だと、溝の立体感（片側が明るい・反対側が暗いという凹凸感）がほとんど分からず平面的に見える。黒系はまだ立体感が見える方だが、それでも足りない。

これを受けて`SandShadingRenderer.swift`（陰影を計算している中心部分）を調整した。

#### 1. 粒状ノイズ（砂のザラザラ感）の直し方

**何が原因だったか**: 砂粒のノイズは「ランダムな模様を作る→少しだけぼかす→コントラストを上げて明暗をはっきりさせる→ごく薄い透明度(3.5%)で上に重ねる」という手順で作っていた。ここに2つの問題があった。
- ぼかしが弱すぎて、粒が1〜2ピクセルしかない小さい単位になっていた（1024ピクセルの画像だと、これは「テレビの砂嵐」に見えるほど細かい）。
- 明暗のコントラストを3.5倍にまで強めていたため、ノイズがほぼ「白か黒かの二択」に近い、まだら模様になっていた。

**どう直したか**: ぼかしをこれまでの3倍以上に強めて粒を大きく・滑らかにし、コントラストの強調もほぼ無し（元の明暗差をそのまま活かす程度）に弱めた。また、「薄い透明度で重ねる」という以前のやり方は、Core Imageの内部ルール（色の値はあらかじめ透明度を掛けた状態で扱う、という前提）と実装が噛み合っておらず、狙った以上にノイズが強く出てしまっていた技術的な不具合もあったため、「明るさを1.0倍とすると、そこから±5%だけ明るい/暗いを振れさせる掛け算」という、もっと単純で誤動作しにくいやり方に作り直した。これにより、「テレビの砂嵐」ではなく「きめ細かい紙やすりのような、滑らかで目立たない粒状感」に近づいたはずである。

#### 2. 立体感（陰影のコントラスト）の底上げ

**何が原因だったか**: 陰影は「砂の色そのもの」を使ったグラデーション画像（ハイライト色→ベース色→シャドウ色）から作っていた。金色のようにハイライト・ベース・シャドウの明るさの差が元々小さい配色を選ぶと、陰影の効果自体も弱く見えてしまう仕組みだった。また、溝の断面をなめらかにしすぎていたため、傾斜がなだらかになり、陰影の明暗の振れ幅が画像の端から端まで十分に到達していなかった。

**どう直したか**: 2段構えで対応した。
- まず、溝の凹凸を誇張する度合い（`reliefScale`、以前は14）を34に、溝の断面のなめらかさ（`smoothingRadius`、以前は6）を3に変更し、輪郭をよりくっきり・急な傾斜にした。これだけで陰影の効き自体が強くなる。
- さらに、「砂の色に関係なく、白に近いハイライト・黒に近いシャドウを持つ、色を無視したグレーの陰影」を同じ溝の形から別途計算し、実際の色付きの陰影の上に「オーバーレイ」という合成方法（明るい面はより明るく、暗い面はより暗くする、写真編集ソフトでもよく使う手法）で重ねる仕組みを追加した。これにより、金色やピンクなど、色そのものの明暗差が小さい配色を選んでも、溝の立体感が一定以上失われないようになった（この「底上げ」の強さも0〜1の数値で調整できるようにしてある）。

#### 3. 見た目を選べるよう、比較用の画像を増やした

上記の調整値（特に立体感の底上げの強さ・粒状ノイズの強さ）は「これが唯一の正解」と決め切れる性質のものではないため、確認用ツール（PreviewTool）を拡張し、以下の7枚をArtifactに含めるようにした。

- `sand-preview-default` / `sand-preview-black-volcanic` / `sand-preview-gold`: 前回と同じ3種類の砂質感を、新しい設定で再生成したもの（前回画像と直接見比べられる）。
- `sand-preview-gold-boost-low` / `sand-preview-gold-boost-high`: 最も立体感が失われやすかった金色で、「底上げ」の強さを弱め(0.30)・強め(0.85)にした場合の比較。
- `sand-preview-black-volcanic-grain-soft` / `sand-preview-black-volcanic-grain-strong`: ノイズが一番目立ちやすい黒系で、粒の強さを弱め・強めにした場合の比較。

`PreviewTool`には`--relief-scale=40`のような引数で、これらの陰影パラメータを一時的に上書きできる仕組みも追加した（将来さらに追加の組み合わせを試したくなった場合に、コードを変更せずコマンドライン引数だけで試せるようにするため）。

## 2026-09-13(3回目): 見本模様を「実際の物理シミュレーションの軌跡」に差し替え、背景に雰囲気（周辺減光・光源方向グラデーション）を追加

前回の粒状ノイズ・立体感の調整（2回目）は解消済みとオーナーに確認いただいた上で、「インスタ映え」としてまだ物足りない点を2つ指摘された。

1. 見本模様が、数式で描いた等間隔の同心円（渦巻き）そのままで単調に見える。
2. 背景（砂全体）が単色のベタ塗りで、雰囲気・奥行きがない。

#### 1. 見本模様を「実際にプレイしたっぽい」軌跡に差し替え

**何が原因だったか**: これまでPreviewTool（GitHub Actionsで見た目を確認するための確認画像）は、検証用として「中心から外側へ均等に広がる渦巻き」を数式でそのまま描いていた。これは意図的な仮の模様であり、実際にアプリで指を使わず端末を傾けて遊んだときにできる、もっと予測できない・有機的な模様とはかけ離れていた。

**どう直したか**: 実際にアプリの中で玉を転がしている物理演算（`GardenPhysics`、傾き→加速→減速→壁での跳ね返り、を計算している部分）に対して、時間とともに向きや強さがゆっくり変化する「仮想の傾き入力」を60秒間与え続け、実際に玉を動かしてできた軌跡をそのまま模様として使うように変更した。仮想の傾き入力は以下の3つの動きを組み合わせている。
- 1〜3秒おきに「だいたいの行き先」をランダムに選び直し、そこへゆっくり向きを変える（完全なランダムでは軌跡が不格好になるため、大きな流れに「意図」を感じさせる）。
- 複数の周期のsine波と小さな乱数を足した、手ぶれのような細かい揺らぎ。
- 中心へ戻ろうとする弱い力を、一定ではなく「呼吸するように」強弱させながら混ぜる。これにより、中心付近まで戻ってくる時期と外周近くまで大きく広がる時期の両方が生まれ、画面全体を使いつつ、同じ場所を何度も通ることによる「溝が交差してより深くなる」表現（もともとある高さの蓄積ロジック）が画像上でもはっきり見えるようになった。

生成のたびに絵柄が変わってしまうと見比べづらいため、乱数の種（シード値）は固定し、GitHub Actionsで再生成しても毎回同じ模様になるようにしてある。パラメータ（向き変更の頻度・中心への引き戻しの強さなど）は、実際にこのセッション内で十数パターン試作して見た目を確認しながら選んだ。

なお、この見本模様の生成ロジックはオンボーディング画面のヒーロー画像とも共有しているため、そちらの見た目も合わせて改善されている。

#### 2. 背景に「雰囲気」を追加（周辺減光・光源方向グラデーション）

**何が原因だったか**: 砂の陰影は、玉が通った溝の周辺にしか出ないため、模様から離れた広い平らな領域は完全な単色のベタ塗りに見えてしまい、写真としての奥行き・雰囲気に欠けていた。

**どう直したか**: Core Imageの標準フィルタだけを使い、以下の2つを画面全体に薄く重ねた。
- 周辺減光（ビネット）: 画面の四隅が少しだけ暗くなる、写真的な効果。
- 光源方向グラデーション: 光が当たっている側（画面の左上寄り）がわずかに明るく、その反対側がわずかに暗くなる、緩やかなグラデーション。

この2つ目のグラデーションの向きは、溝の陰影計算に使っている光源の設定（`LitSphereImageGenerator`が持つ光源の向き）と同じ値をそのまま使っており、「同じ方向から環境光が回り込んでいるように見える」という一貫性を持たせている。どちらの効果も強さを数値で調整でき、必要なら0にして無効化できる。

#### 3. 比較用の画像を追加

これまでの`sand-preview-default` / `black-volcanic` / `gold`とそのバリエーションに加え、背景の雰囲気の強さを弱め・強めにした比較画像を2枚追加し、PreviewToolの出力を合計9枚にした。

- `sand-preview-default-vignette-soft` / `sand-preview-default-vignette-strong`: 周辺減光・光源方向グラデーションの強さ違いの比較。

`--vignette-intensity=` `--ambient-directional-strength=` という引数でも一時的に強さを上書きできるようにした（既存の`--relief-scale=`などと同じ仕組み）。

#### ビルド確認・事前検証について
