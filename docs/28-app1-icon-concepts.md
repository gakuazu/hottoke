# アプリアイコン案（トキノワ）

作成日: 2026-09-26
担当: ux-designer
比較Artifact（非公開・オーナーのみ閲覧可）: https://claude.ai/artifact/VMQpRz9y5BzKHSBNthuHLL

## 前提（現状の確認）

アプリアイコンはこれまで一度も作っていない（`Assets.xcassets`にAppIconセット自体が存在しない）ため、今回が実質はじめての作成になる。作業はまずデザイン案の比較・決定までとし、実際に`Assets.xcassets`へ組み込む作業（各サイズのPNG書き出し・Xcodeプロジェクトへの登録）はオーナーが案を選んだ後、ios-engineerに引き継ぐ。

## デザインの前提にしたこと

- アプリ名「トキノワ」＝「時の輪」。24時間を1つの輪として、その日の活動を毎日自動で描くアプリであること。
- 文字・ロゴ文字は一切使わない（Appleの推奨どおり）。
- ごく小さいサイズ（ホーム画面で60〜180pt程度）でも一目で分かる、大胆でシンプルな形にする。細い線や点描のような繊細な模様は、実際のアプリの絵では使っているが、アイコンでは潰れて見えなくなるため避けた。
- 背景は常にアプリと同じ「暗い夜空色」で統一。
- 使う色は、アプリ内で実際に活動の種類ごとに使っている色（静止=明るい青、睡眠=暗い藍、歩行=ミント、ランニング=ピンク赤、自転車=琥珀、乗り物=明るい紫）をそのまま流用し、アプリ本体を開いたときの絵との一貫性を持たせた。

## 4つの案

### A：光の輪（もっともシンプルな案）

1本の光る輪と、輪の一番上にある小さな光の点（「今」の位置）だけで構成した、要素が最も少ない案。輪の色はミント〜ブルーのグラデーション。

- **向いている理由**: 形が単純なので、どんなに小さく表示されても絶対に潰れない。実装・書き出しのコストも最小。「まず失敗しない安全な案」を選びたい場合におすすめ。
- **弱み**: 4案の中では最も無地に近く、個性やアプリらしさ（活動の色の多さ）は伝わりにくい。

### B：時計の文字盤（配色でアプリらしさを出す案）

輪を6つの弧に分け、それぞれをアプリ内で実際に使っている6色（静止・睡眠・歩行・ランニング・自転車・乗り物）で塗り分けた案。色の並びが時計の文字盤のようにも見える。

- **向いている理由**: アプリを開いたときに見える絵との「色の統一感」が4案の中で最も強い。「時の輪」という名前も、時計の文字盤のイメージで伝わりやすい。
- **弱み**: 色の数（要素）がAより多いため、極端に小さいサイズ（60px以下）では色の境目がやや見分けにくくなる可能性がある。比較Artifactの「小サイズ」の行で実際の見え方を確認できる。

### C：花のコロナ（簡略版）（アプリの標準表現と直結させる案）

アプリの現在の標準表現である「花のコロナ」（時間のリングから花びらが外へ開く表現）を、5枚の花びらだけに思い切って単純化した案。花びらの色は活動の色から5色を選んだ。

- **向いている理由**: アプリを実際に開いたときに見える絵と一番強くつながる（「これがあの模様のアプリだ」と一目で連想しやすい）。
- **弱み**: 花びらの形はA・Bより複雑なため、極小サイズでの見分けやすさはやや劣る。将来アプリの標準表現が変わった場合、アイコンとの対応関係が薄れる可能性がある。

### D：満ちていく輪（自由発想・目立ちやすさ重視の案）

輪の一部分（約4分の3）だけが暗い藍〜青〜ミント〜明るい黄へと色を変えながら光っていて、光っている先端に「今」を示す明るい点がある案。暗い部分と明るい部分のコントラストが強く、時間が少しずつ満ちていくイメージを表現している。

- **向いている理由**: コントラストが強いぶんホーム画面で目立ちやすく、他の3案とは違う独自の形（輪が全部閉じていない）で個性が出せる。「時間が進んでいく」という、アプリの本質的な仕組みをA・Bよりも動的に表現できる。
- **弱み**: 「輪が閉じていない」という形は、見る人によっては「輪」というより「弧」に見える可能性があり、A・Bほど直接的に「輪」を連想させないかもしれない。

## 選ぶときの視点（比較Artifactの末尾にも同内容を記載）

- とにかく潰れにくさ・視認性を優先するなら → **A**
- アプリ本体との一体感を優先するなら → **B** か **C**
- ホーム画面での目立ちやすさ・個性を優先するなら → **D**
- 気に入った案が複数ある、または「Aの形にBの配色を使いたい」のような組み合わせ・微調整の希望があれば、比較Artifactを見ながら伝えてもらえればすぐに調整できる。

## 次のアクション

1. オーナーが比較Artifactを見て、4案から1つ（または組み合わせ案）を選ぶ、もしくは修正指示を出す。
2. 決定後、選ばれた案を仕上げ（必要な微調整）た上で、実際のAppIcon画像（1024×1024の基準サイズ、iOSが自動で角丸マスク・各解像度への縮小を行う）を書き出す。
3. ios-engineerに引き継ぎ、`Assets.xcassets`にAppIconセットを新規作成してXcodeプロジェクトに登録してもらう（GitHub Actionsでのビルド確認込み）。
